# Язык структурированных запросов

--------------------------------

Вы работник компании, занимающейся изобретением велосипедов. Для учёта моделей велосипедов компании необходимо
организовать базу данных. Вам поступила задача разработать СУБД и модель данных... Чтож, кто вы такой, чтобы спорить с
начальством?

## 1. Разработать формальную грамматику языка структурированных запросов

Разрабатываемый язык является регистрозависимым.
Язык должен поддерживать следующие литералы:

- целочисленные константы - совокупность цифр. Допускается разделение разрядов символом "_", если он стоит не на границе
  числа (например, `1_000_000`);
- вещественные константы - совокупность цифр и символа ".". Допускается разделение разрядов символом "_", если он стоит
  не на границе числа и не стоит рядом с ".";
- строковая константа - любой текст, заключенный между символами двойных кавычек `"`, символ экранирования `\`;
- логическая константы - терминалы `true` и `false`;
- указатель отсутствия данных - терминал `null`;
- имя - набор букв, цифр и символов `[_$]`, не начинающийся с цифры.

### Подмножество языка для управления базами данных и отношениями

Отношение используется в своем значении из дискретной математики - множество упорядоченных кортежей, каждой позиции в
кортеже соответствует домен, описанный именем, типом данных и ограничением целостности (notnull, unique и т.д.).

Подмножество языка, отвечающее за управление базами данных и отношениями, должно поддерживать следующие конструкции:

- `createDatabase(<Строковый литерал>);`, предложение создания базы данных. Строковый литерал указывает название базы
  данных;
- `deleteDatabase(<Строковый литерал>);`, предложение удаления базы данных и всех её отношений. строковый литерал
  указывает название базы данных;
- ```
  [<тип индексации>] relationship <название> {
        // описания столбцов отношения, разделенные ';'
        // описание ограничений, разделенные ';'
  };
  ```
  предложение создания нового отношения.  
  Тип индексации задает то, как отношение хранится в памяти. Может принимать значения `ordered`, `hashtable` и `tree`.
  Подробнее об индексации ниже.
- `<модифицаторы, разделенные пробелами> <тип данных> <имя>` - описание столбца отношения. Доступные модификаторы
  столбца и типы данных описаны ниже;
- `<имя отношения>.addConstraint<ТипОграничения>(<имя ограничения>, <список имен>);` - описание простых именованных
  ограничений. Типы ограничений приведены ниже. Может использоваться внутри блока relationship, тогда указание имени
  отношения не обязательно;
- `<имя отношения>.addForeignKey(<имя ограничения>, <имя отношения>, <соотвествие>[, <соотвествия>]);` - описание
  внешних ключей. Если первичный ключ другого отношения составной, задается список соответствий, разделенных запятой.
  Может использоваться внутри блока relationship, тогда указания имени отношение не обязательно;
- `<имя> -> <имя>` - соответствие внешнего ключа текущего отношения первичному ключу другого;
- `<имя отношения>.addColumns({<описания добавляемых столбцов, разделенных ';'>});` - добавление новых столбцов в
  отношение;
- `<имя отношения>.editColumn(<имя столбца>, {<новое описание столбца>});` - изменение столбца в отношении;
- `<имя отношения>.removeColumn(<имя столбца>);` - удаление столбца из отношения;
- `<имя отношения>.removeColumns(<список имен столбцов>);` - удаление столбцов из отношения;
- `deleteConstraint(<имя ограничения>);` - удалить именованное ограничение;
- `deleteRelationship(<имя отношения>);` - удаление отношения из базы данных.

Для отношений поддерживаются следующие типы индексации:

- `ordered` - отношение хранится как отсортированный по ключу вектор. Выборка по ключу осуществляется с помощью
  бинарного поиска;
- `hashtable` - отношение хранится на хэш таблице, выборка по ключу осуществляется за O(1);
- `tree` - отношение хранится на дереве, выборка по ключу осуществляется за O(log n);
- без индексации. Отношение хранится на векторе, соблюдение порядка не гарантируется. Поиск за O(n).

Невозможно создать индексированную таблицу, если в ней не определен первичный ключ.

Столбцы могут иметь следующие типы данных:

- `String` - строковые литералы и `null`;
- `Boolean` - логические значения (`true`, `false` и `null`);
- `Integer` - целочисленные значения и `null`;
- `Real` - вещественные значения и `null`.

Столбцы могут иметь следующие модификаторы:

- `primary` - столбец является первичным ключом;
- `unique` - значение данного столбца не могут повторяться в рамках отношения;
- `notnull` - значение данного столбца не могут быть null.

К простым ограничениям целостности относятся:

- `Unique` - совокупная уникальность столбцов. Строки конфликтуют только если ВСЕ перечисленные столбцы одновременно
  имеют одинаковые значения;
- `Primary` - создание составного первичного ключа. Если в таблице уже задан первичный ключ, то данная операция
  возвращает ошибку;
- `Predicate` (Опционально) - вместо списка имен вторым аргументом идет логическое выражение. При вставке в отношение
  новой строки, она проверяется на соответствие предикату, если предикат вернул false, то вставка не происходит.

### Подмножество языка для осуществления запросов

Запрос на получение строк отношения имеет следующий вид:
`<отношение>.findIf(<условие>);`, условие - выражение, которое
возвращает логическое значение.  
Под отношением подразумевается или имя отношения, или результат выражения, возвращающего отношение (например, `findIf`,
`join`).

Выражение может содержать литералы, арифметические и логические операторы в стиле Си, ссылки на столбцы
отношения. Если имеет место конфликт имён столбцов, используется конструкция вида
`<имя отношения>::<имя столбца>`.

Выражения так же могут содержать подзапросы, валидация типа данных результата выполнения подзапроса выполняется во время
исполнения.  
Например, допустимо писать выражение вида `a == SecondRel.findIf(b == 1).project(с)`. Здесь мы из отношения
`SecondRel` получили строки, в которых столбец b равен 1, из этих строк взяли только столбец "c", выражение проверяет,
что в текущем отношении столбец a равен найденному значению.

Над отношениями определены следующие операции:

- `<отношение>.project(<список имен столбцов>)` - данная операция оставляет только те столбцы отношения, которые
  перечислены;
- `<отношение>.map(<описатель объекта>)` - каждая строка текущего отношения заменяется на новую по правилу, заданному
  описателем (см. ниже). Может применяться для добавления столбцов, основанных на сложных выражениях, а также для
  изменения порядка и названия столбцов;
- `<отношение>.sort(<список описателей сортировки>)` - сортировка отношения, описатель сортировки -
  `[asd|desc] <имя столбца>`;
- `<отношение>.limit(<число>)` - оставить только первые n строк отношения;
- `<отношение>.skip(<число>)` - отбросить первые n строк отношения;
- `<отношение>.join(<отношение>, <условие соединения>)` - выполняет внутреннее сцепление двух отношений по условию;
- `<отношение>.leftJoin(<отношение>, <условие соединения>)` - выполняет левое сцепление двух отношений по условию;
- `<отношение>.rightJoin(<отношение>, <условие соединения>)` - выполняет правое сцепление двух отношений по условию;
- `<отношение>.fullJoin(<отношение>, <условие соединения>)` - выполняет полное сцепление двух отношений по условию;
- `<отношение>.group(<список столбцов>, <описатель объекта>)` - аналог group by из sql. Группировка по совокупной
  равности столбцов. Неупомянутые в списке столбцы могут входить в описатель объекта только как аргументы агрегирующих
  функций.

Под условиями понимаются выражения, результатами вычислений которых являются логические значения.
Доступны следующие агрегирующие функции:

- `min(<выражение>)`/`max(<выражение>)` - самый маленький/большой элемент в группе. null, если все элементы в группе
  null;
- `sum(<выражение>)` - сумма всех элементов в группе. null игнорируются. null, если все элементы в группе null;
- `groupSize()` - размер группы;
- `reduce(<выражение>, <выражение>)` (опционально) - произвольная свертка. Первое выражение задает начальное значение,
  второе значение задаёт правило накопления, в этом выражении можно сослаться на текущий накопленный результат
  `current`. Например, накопление произведения элементов столбца `a` можно будет задать так:
  `prodA = reduce(1, current * a)`

Так же для отношений доступны следующие свойства:

- `<отношение>.count()` - возвращает количество строк в отношении;
- `<отношение>.isEmpty()` - аналогично `<отношение>.count() == 0`;
- `<отношение>.anyMatch(<логическое выражение>)` - true, если хотя бы одна строка соответствует выражению;
- `<отношение>.allMatch(<логическое выражение>)` - true, если все строки соответствует выражению;
- `<отношение>.contains(<выражение>)` (опционально) - сокращенный синтаксис для
  `<отношение>.anyMatch(<имя столбца> == <выражение>)`. Может использоваться только на отношениях, которые состоят
  только из одного столбца (за счёт чего упоминать название столбца нет необходимости).

Описатель объекта:

```
row {
    <имя столбца1> = <выражение1>;
    <имя столбца2> = <выражение2>;
    ...
}
```

Запрос на вставку имеет следующий вид: `<имя отношения>.insert(<описатель объекта>);`.

Запрос на удаление имеет следующий вид: `<имя отношения>.removeIf(<условие удаления>);`.

Так же в контексте выражений определены глобальные функции, на которые можно ссылаться.
Обязательно к реализации функция `match(<строковый литерал>, <выражение>)`. Она возвращает true, если заданная
выражением строка удовлетворяет регулярному выражению, заданному строковым литералом.

## 2. Разработать интерпретатор запросов к СУБД

Разработать Систему Управления Базами Данных (СУБД). Система состоит из сервера, обрабатывающего запросы, используя на
транспортном уровне TCP, и клиента, который позволяет отправлять запросы, введенные пользователем с клавиатуры.

Система должна поддерживать следующие операции:

1. Создание/удаление базы данных;
2. Создание/удаление отношений базы данных;
3. Добавление/изменение/удаление столбцов в отношениях;
4. Запросы получения и изменения информации.

Запросы, которые подразумевают работу с конкретной базой данных, должны содержать имя базы данных в URL.  
Допустимо использовать HTTP протокол с передачей запроса как `plain text`.
Пример возможных ЭП:

- `http://host:port/` - обрабатываются только запросы создания и удаления базы данных;
- `http://host:port/{database}` - обрабатываются все запросы.

(Опционально) - создать свой протокол, работающий на TCP сокетах, чтобы в URL можно было писать заголовок не "http://",
а "mydb://" или что-то ещё.

# 3. Разработать модель данных для учёта моделей велосипедов

Используя разработанную СУБД разработать модель данных. Имеются следующие сущности:

Компонент велосипеда - id, тип компонента (руль, рама, колесо, седло и т.д.), название, описание компонента, стоимость
компонента;  
Велосипед - id, название, описание, список компонентов, из которых состоит (можно указать количество данного компонента
в велосипеде).

Составить запрос, который позволяет получить стоимость велосипеда (как сумму стоимости компонентов велосипеда, с учетом
кратности их использования).
